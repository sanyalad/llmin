# Sandbox execution

Stage 1 не исполняет произвольный shell. План может вызывать только зарегистрированные типизированные capabilities, которые одновременно разрешены конкретным `TaskSpec`.

## Текущие capabilities

- `read_text` — чтение существующего UTF-8 файла внутри sandbox;
- `write_text_atomic` — атомарное создание или изменение UTF-8 файла из точного writable allowlist.

## Инварианты

- sandbox root существует до начала исполнения;
- task paths относительные, нормализованные и используют `/`;
- writable allowlist сравнивается по точному пути;
- абсолютные пути, `..`, неоднозначная нормализация и Windows-разделители запрещены;
- любой симлинк в writable-маршруте запрещён;
- родительская директория создаваемого файла должна уже существовать;
- размер чтения и записи ограничен;
- elapsed budget проверяется до и после каждого capability;
- запись выполняется через временный файл в той же директории и `os.replace`;
- исходные байты сохраняются в памяти транзакции;
- ошибка любого последующего action откатывает предыдущие записи;
- plan/task identity, action budget и capability permissions проверяются до исполнения.

## Ограничения прототипа

Текущая транзакция защищает только от ошибок внутри одного процесса. Timeout обнаруживает превышение после возврата capability, но пока не прерывает зависший системный вызов. Sandbox также не защищает от одновременного внешнего изменения файлов между проверкой пути и записью. До поддержки недоверенных параллельных процессов потребуется отдельный worker/container, принудительное завершение по deadline и повторная проверка файловых дескрипторов.
